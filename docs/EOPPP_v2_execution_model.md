# EOPPP 2.0 실행 모델 (기획 초안)

> 상태: **가정 기반 초안 + 동작하는 구현** (branch `2.0`). 2.0 하드웨어 명세가 나오면 아래 가정(M*)을 명세에 맞춰 고치고,
> 코드에서 같은 번호를 참조하는 부분(`# [M2]` 등)만 수정한다.
> 1.0(현재 하드웨어)은 `main` 브랜치의 동작을 그대로 따른다.

---

## 1. 목표

1.0은 "함수 = 초기화 GPC + 연산 GPC 1개, 연산 GPC를 반복하다 조건이 참이면 다음으로"라는
고정 구조라서 다음을 표현할 수 없다.

- 함수 안의 루프 여러 개, 중첩 루프
- 루프 안 `if` (조건부 실행)
- 한 반복 안에서 앞 결과를 쓰는 연쇄 계산 (곱셈·뺄셈 포함)
- 루프 전후의 일반 계산, 함수 호출과 반환값

2.0은 GPC를 **글로벌 클럭에 따라 진행하는 프로그램 카운터**로 보고, 함수를
**클럭 단위 행(row)의 시퀀스와 분기**로 컴파일한다.

---

## 2. 실행 모델 가정

| 번호 | 가정 | 근거 |
|---|---|---|
| **M1** | 한 클럭에 GPC 값 g에 해당하는 행 하나를 실행한다. 코어 c는 주소 `g*128 + c`의 Z/Y를 실행한다. 모든 코어는 **이전 클럭이 끝난 시점의 X**를 읽고, 결과는 클럭 끝에 X에 쓴다. | 1.0 검증 동작, 논문 §2.1 |
| **M2** | 다음 GPC: 행에 분기 코어(EQZ…GTEZ + BRGPC_HOLD)가 있으면, 조건이 참인 분기 코어의 X 값으로 이동한다. 분기 코어가 있는데 아무것도 참이 아니면 **같은 행을 반복**한다. 분기 코어가 없으면 `g+1`로 간다. | 1.0 (초기화 행 → 연산 행 진행, 연산 행 반복) |
| **M3** | 분기 코어의 X는 분기 연산으로 바뀌지 않는다 (목표 GPC를 담는 용도). | 1.0 (조건 코어 초기값 = 목표 GPC) |
| **M4** | 앞/뒤 임의 GPC로 분기할 수 있다. | 사용자 확인 (2026-10) |
| **M5** | 행이 바뀌어도 self-routing 코어(ADD, 소스 = 자기 자신)는 X를 유지한다. Z=0, Y=0 코어는 X=0이 된다. | 사용자 확인, 1.0 동작 |
| **M6** | 연산: `ADD` X←Σ X[s] (Y-마스크, s−c ∈ [−16,+15]) / `SMT` X←X·Y (부호, 하위 32비트) / `SRSH` X←X>>Y (산술) / `LXY` X←Y. 분기 조건은 Σ에 대해 `GTZ`(>0), `GTEZ`(≥0), `EQZ`(=0), `NEQZ`(≠0). | 1.0 인코딩, 논문 Table 1 |
| **M7** | A-bank: `ADD + XD_MEM + A_BANK_RD`(주소 증가) 코어는 그 행이 실행될 때마다 자기 A-bank의 다음 원소를 X로 읽는다. `A_BANK_WR`(주소 증가) 코어는 계산 결과를 다음 주소에 쓴다. 주소는 0에서 시작한다. | 1.0 FIR 구성 |
| **M7a** | `LXY`는 그 코어의 A-bank 주소를 0으로 되돌린다. 함수에 들어갈 때(초기화 행) 외부 로더가 그 함수의 배열 A-bank를 C 초기값으로 채운다. | 가정 (함수마다 스트림을 처음부터 읽기 위함) |
| **M8** | 같은 행에서 분기 코어 둘 이상이 동시에 참인 경우의 우선순위는 **미정**. 컴파일러는 항상 **정확히 하나만 참이 되도록** 분기를 만든다. | 미확인 → 회피 |

### 2.0이 쓰지 않는 것 (의미 미확인)

| 구성 | 이유 | 대안 |
|---|---|---|
| `SUM_NEG` | 무엇을 부정하는지 미문서화 | 부정은 `SMT ×(−1)`로 만든다 |
| `LSH`, `LTZ`, `LTEZ` | FPGA 미검증 | 왼쪽 시프트는 `SMT ×2^k`, 비교는 `GTZ/GTEZ`로 바꾼다 |
| `XX_LEFT_XD`, `Y_LEFT_XD` | 1.0 MAC 경로에서만 검증 | 일반 경로는 자기 코어 연산만 쓴다 |
| CALL/RETURN, r126/r127 루프 레지스터 | 하드웨어 미동작 | 컴파일 시점 인라이닝 |

`SRSH`, `EQZ`, `NEQZ`는 ISA 문서에 있으나 FPGA 미검증이므로, 사용 시 metrics에 표시한다.

## 3. 컴파일 구조

```
C ─ GCC ─ GIMPLE SSA ─┬─ 1.0 빠른 경로 (루프 1개를 1행으로, MAC 환원 트리)
                      │     └ 한 함수라도 거부되면 프로그램 전체를 ↓
                      └─ 2.0 일반 경로
                           GIMPLE → 2.0 IR (기본 블록, 변수, PHI 제거)      v2/lower.py
                           → 인라이닝 (재귀 없는 사용자 함수)               v2/inline.py
                           → 같은 a[i] 재사용 · 스트림 조건 S1–S4 검사      v2/streams.py
                           → 마이크로 연산 선택 (한 연산 = 한 코어 · 한 클럭) v2/backend.py
                           → 코어 배치 (담금질) + 릴레이 / 상수 복제본
                           → 블록별 행 스케줄링 (의존성 순서)
                           → 블록 배치 · 분기 코어 · 초기화 행
                           → Z/Y 인코딩 → MIF + symbols.json               v2/program.py
```

`main.py`의 `EOPPP_V2` 환경 변수로 고른다.

| 값 | 동작 |
|---|---|
| `auto` (기본) | 모든 함수가 1.0을 통과하면 1.0 출력 (main과 비트 동일), 아니면 프로그램 전체를 2.0으로 |
| `off` | 1.0만 (`evaluation/rerun_eval.py`가 사용) |
| `force` | 2.0만 (`evaluation/v2_difftest.py`가 사용) |

1.0 함수와 2.0 함수는 한 MIF에 섞지 않는다. 1.0 코드는 `SUM_NEG`, `XX_LEFT_XD` 등
2.0 모델(M1–M8)이 정의하지 않는 구성을 쓰기 때문이다.

### 3.1 함수 레이아웃

```
GPC g0       : 초기화 행 (LXY: 변수 초기값, 상수, 분기 목표 GPC)
GPC g0+1 …   : 기본 블록들의 행 (블록 순서대로 배치)
마지막 블록   : 반환 → 다음 함수의 첫 GPC (프로그램 끝이면 정지 행)
```

함수끼리는 1.0과 같이 순서대로 놓고, 함수가 끝나면 다음 함수 GPC로 넘어간다.
프로그램의 마지막에는 자기 자신으로 분기하는 정지 행을 둔다.

### 3.2 마이크로 연산 (모두 M6의 연산만 사용)

| C 연산 | 행 수 | 구현 |
|---|---|---|
| `d = a` | 1 | d: ADD [a] |
| `d = a + b` | 1 | d: ADD [a, b] (a = b면 `d=a; d*=2`) |
| `d = a - b` | 1(+2) | d: ADD [a, nb], nb = −b (상수면 상수 코어, 아니면 `nb=b; nb*=−1`) |
| `d = a * k` | 2 | `d=a; d*=k` (d = a면 1) |
| `d = a << k` | 2 | `d=a; d*=2^k` |
| `d = a >> k` | 2 | `d=a; d>>=k` (SRSH, 미검증 표시) |
| `d = x[i]` | 2 | 배열 코어: A-bank 읽기 → `d=arr` |
| `y[i] = v` | 1 | 배열 코어: ADD [v] + A-bank 쓰기 |
| 변수 × 변수 | — | 하드웨어 연산 없음 → 거부 |

### 3.3 분기 (M2, M8)

블록 끝 조건 `if (a OP b) goto T else F`는 서로 보완인 분기 코어 2개로 만든다.
둘 중 정확히 하나만 참이므로 우선순위(M8)에 의존하지 않는다.

| OP | T로 가는 코어 | F로 가는 코어 |
|---|---|---|
| `>`  | GTZ(a − b)  | GTEZ(b − a) |
| `>=` | GTEZ(a − b) | GTZ(b − a) |
| `<`  | GTZ(b − a)  | GTEZ(a − b) |
| `<=` | GTEZ(b − a) | GTZ(a − b) |
| `==` | EQZ(a − b)  | NEQZ(a − b) |
| `!=` | NEQZ(a − b) | EQZ(a − b) |

`x − y`는 `x + (−y)` 합으로 만든다 (부정 코어). 무조건 분기는 자기 X(= 목표 GPC ≥ 1)를
검사하는 `GTZ` 코어 하나라서 상수 코어가 필요 없다. 분기 코어는 X에 목표만 담고 자기 행에서만
동작하므로 **목표 GPC마다 코어 하나**를 함수 전체에서 공유한다.
다음 블록이 바로 뒤 행이면 분기 코어 없이 넘어간다 (M2: g+1).

### 3.4 스케줄링 규칙 (M1)

블록 안 연산 u, v (u가 먼저)에 대해

- 읽기-쓰기(RAW): v가 u의 결과를 읽으면 `row(v) > row(u)`
- 쓰기-읽기(WAR): v가 u가 읽는 코어에 쓰면 `row(v) ≥ row(u)` (같은 클럭에는 옛값을 읽음)
- 쓰기-쓰기(WAW): `row(v) > row(u)`
- 코어 하나는 한 행에 연산 하나
- 분기 코어는 블록의 마지막 행에 둔다

같은 행의 연산은 모두 병렬로 실행된다. 이것이 공간 병렬성이다.

### 3.5 코어 배치

연결 = (읽는 코어, 읽히는 코어). 목표는 모든 연결이 윈도우 `[−16, +15]` 안에 들도록
126개 슬롯에 코어를 놓는 것이다.

1. Reverse Cuthill–McKee 순서로 슬롯 전체에 고르게 펼친다 (빈 슬롯이 사이에 남도록).
2. 담금질(simulated annealing, seed 0 고정 → 결정적)로 위반 연결 수를 줄인다.
3. 남은 위반 연결마다 경유 코어를 하나 끼운다. 상수면 **복제본**(LXY 초기값만, 실행 비용 0),
   변수면 **릴레이**(복사 1행). 경유 코어를 포함해 다시 담금질 … 위반이 0이 될 때까지.
4. 블록 코드에 릴레이 복사를 넣는다. 한 블록 안에서는 소스가 다시 쓰이기 전까지
   이미 복사한 경로를 재사용한다. 릴레이도 일반 연산과 같은 의존성으로 스케줄된다.

부호 반전 임시 코어는 4개를 돌려 쓴다 (블록 안에서 바로 소비되므로, 순서는 WAR/WAW 규칙이 보장).

### 3.6 함수 호출

재귀가 없는 사용자 함수 호출은 2.0 IR에서 인라이닝한다. 인자는 매개변수 변수에 복사하고,
반환은 반환값 변수에 복사한 뒤 호출 지점의 다음 블록으로 간다.
하드웨어 CALL/RETURN이 동작하게 되면 이 단계를 바꾼다.

### 3.7 GIMPLE → IR (out-of-SSA)

- SSA 버전은 기본 변수 이름으로 합친다. 생존 구간이 겹치는 버전(간섭)은 새 이름(`acc.1`)을 받는다.
  이름 없는 임시값은 `t.<버전>`.
- PHI는 선행 블록 끝의 복사가 된다. 선행 블록의 후속이 둘 이상이면(임계 간선) 간선을 쪼갠다.
  한 간선의 복사는 병렬 복사이므로 서로 겹치면 임시값을 거친다.
- 받는 타입: 32비트 부호 정수만. 64비트·부호 없는·실수·포인터·구조체·전역 스칼라·switch·
  나눗셈/나머지/비트 연산·재귀는 거부한다 (모두 이유와 함께 `v2.log`, `checker.log`에 기록).

### 3.8 배열 스트림 조건 (M7, M7a)

A-bank는 접근마다 주소가 1 증가하므로, `a[i]`가 C 의미와 같으려면

| 조건 | 내용 |
|---|---|
| S1 | 배열마다 접근 지점 하나 (읽기 전용 또는 쓰기 전용). 같은 블록의 같은 `a[i]` 재읽기는 첫 값을 복사해 하나로 만든다 |
| S2 | 접근을 품은 루프가 정확히 하나 (바깥 루프가 있으면 주소가 0으로 돌아가지 않음) |
| S3 | 접근 블록이 루프의 모든 latch를 지배 (반복마다 정확히 한 번) |
| S4 | `i`는 유도 변수: 루프로 들어오는 모든 경로에서 `i = 0`, 루프 안 정의는 `i = i + 1` 하나, 접근 뒤에 실행 |

## 4. 검증 방법

- `gcc_eoppp/v2/sim.py`: M1–M8을 그대로 실행하는 MIF 시뮬레이터
- `evaluation/v2_difftest.py`: 같은 C를 PC에서 실행한 결과(배열, 반환값)와
  MIF를 시뮬레이터로 실행한 결과를 비교

- `evaluation/v2_ir_fuzz.py`: 무작위 구조적 IR(중첩 루프, if/else, 산술, 스트림)로 백엔드만 검증

시뮬레이터는 가정을 정의하는 기준이므로, 명세가 나오면 **시뮬레이터 → 코드 생성** 순서로 맞춘다.

### 4.1 결과 (2026-10-27, 가정 M1–M8 기준)

| 대상 | 일치 | 불일치 | 거부 | 비고 |
|---|---|---|---|---|
| `eoppp_v2_test.c` (4 함수) | 4/4 | 0 | 0 | 인라이닝·중첩 루프·while·루프 안 if, 81 행 |
| `eoppp_v2_kernels.c` (3 함수) | 3/3 | 0 | 0 | prefix_sum, first_diff, moving_sum4 |
| 경계 프로그램 39 | 17 | 0 | 22 | 중첩 루프·goto 통과(1.0은 거부). 거부: 타입, 연산, 코어 수(변수 125개 이상) |
| RTPG 10,000 | 3,472 | 0 | 6,528 | 1.0 통과 2,590. 거부: float/union/struct/enum, 재귀, malloc, 간접 인덱스 |
| IR 무작위 300 × 2 seed | 182 / 188 | 0 | 118 / 112 | 거부는 모두 코어 수(126) 초과 |

불일치 0은 **가정 M1–M8 아래에서** 번역이 정확하다는 뜻이다. 하드웨어가 가정과 다르면
시뮬레이터를 고친 뒤 같은 시험을 다시 돌린다.

## 5. 하드웨어 확인 필요 사항

1. M2: 분기 코어가 있는데 아무것도 참이 아닐 때 같은 행을 반복하는가 (1.0과 같은가)
2. M3: 분기 연산이 분기 코어의 X를 바꾸지 않는가
3. M6: SMT 결과는 하위 32비트인가, 상위 비트(Q 포맷)인가
4. M7: A-bank 주소는 행이 실행될 때마다 증가하는가, 클럭마다 증가하는가
5. M8: 분기 코어 여러 개가 동시에 참일 때의 우선순위
6. `SUM_NEG`, `LSH`, `SRSH`, `LTZ`, `LTEZ`, `EQZ`, `NEQZ`의 정확한 의미
7. 글로벌 클럭 모델에서 함수 전환 시 코어/뱅크 상태 규칙 (초기화 행의 필요 여부)
8. M7a: LXY가 A-bank 주소를 0으로 되돌리는가, 함수 입력 배열을 누가 언제 채우는가

## 6. 알려진 한계

- 1.0 전용 함수(64비트 MAC FIR 등)와 2.0 전용 함수(중첩 루프 등)가 한 프로그램에 함께 있으면
  `auto`는 2.0으로 가고, 1.0 전용 함수가 거부되어 MIF가 나오지 않는다.
- 2.0은 상수·분기 목표마다 코어를 쓰므로, 변수가 많은 함수는 1.0보다 먼저 코어 한도에 닿는다.
- 변수 × 변수 곱셈은 하드웨어 연산이 없어 거부한다 (2.0 명세에 곱셈기가 있으면 추가).
